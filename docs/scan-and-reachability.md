## 1. Network Discovery & Port Scanning

### 1.1 Discovery Liveness (§11)
Before launching port scans, the scanner validates host liveness using multi-modal probes:
- **ARP Ping:** Used for local L2 broadcast domains to detect live MAC addresses instantly.
- **ICMP Echo:** Standard network layer ping.
- **TCP SYN Ping:** Probes high-frequency ports (21, 22, 80, 443, 445, 3389, 8080, 8443). If any port responds with SYN/ACK or RST, the host is confirmed online.

### 1.2 Adaptive Port Scanning (§12)
Rather than blindly probing 65,535 ports on every scan:
1. **Default Profile:** Curated top 1,000 ports derived from real-world frequency data.
2. **Adaptive Mode:** Checks previously discovered open ports on every scan plus a rotating 10% sample of the remaining port range, achieving complete port space coverage every 10 cycles with a fraction of network overhead.

### 1.3 Rate Limiting & Congestion Safety (§13)
- **Token Bucket Rate Limiter:** Enforces a configurable Packets-Per-Second (PPS) ceiling (e.g. 2,000 PPS).
- **Fragile Device Avoidance:** Devices detected as printers or industrial controllers are immediately shifted to passive or gentle inspection profiles to avoid device lockups.

## 2. Service & Protocol Interrogation (§14)

Once ports are identified as open, protocol interrogation extracts banners, versions, and cryptographic attributes:
- **SSH:** Interrogates protocol version string and banner (e.g. `SSH-2.0-OpenSSH_9.6p1`).
- **HTTP / HTTPS:** Interrogates `Server` and `Via` headers without following redirects to evaluate actual web servers (Nginx, Apache, Varnish).
- **TLS Interrogation (§14.5):** Establishes handshakes across TLS 1.0, 1.1, 1.2, and 1.3. Analyzes cipher suites, certificate subjects, SAN lists, validity windows, and self-signed status.
- **Database Probing:** Safe initial handshake decoding for MySQL and Redis.
- **Banner Hashing (§6.4):** Computes SHA256 hashes of raw service banners to trigger automated, targeted rescans whenever an asset's banner changes.

## 3. The Two-Tier Reachability Engine (§1.2, §38.4)

Reachability analysis is Sieve Security's core technical differentiator. It filters out up to 80% of vulnerability noise by proving whether vulnerable code is actually exposed to attack vectors.

### Reachability Hierarchy

```
[ Tier 1: Socket & Network Reachability ]
  - Is the port open externally (0.0.0.0:* or [::]:*)?
  - Does the socket bind to a running process on the OS?
  - Resolves /proc/<pid>/exe and socket inode via authenticated collector or agent.
                 │
                 ▼
[ Tier 2: Runtime Code & Symbol Reachability ]
  - Is the vulnerable shared library (.so / .dll) mapped into process memory?
  - Are vulnerable function symbols executed (eBPF uprobe/kprobe tracking)?
```

### Reachability Classifications:

| State | Definition | Actionable Priority |
|---|---|---|
| `listening_and_loaded` | Port is publicly accessible, bound to a process, and the vulnerable component is actively loaded in memory. | **Tier 1 (Highest)** |
| `listening_process` | Port is open on network interfaces and mapped to an active binary. | **High** |
| `installed_and_running` | Vulnerable package is running as a local background process (not network-facing). | **Medium** |
| `installed_not_running` | Package exists on disk (e.g. installed utility), but no active process executes it. | **Low** |
| `not_loaded` | Package present on disk, verified NOT mapped into memory. | **Informational** |

### Distro Backport Awareness (§14.6)
Enterprise distributions (Debian, Ubuntu, RHEL, SUSE) backport security patches into older upstream versions (e.g. Ubuntu patching OpenSSL `3.0.8` with version `3.0.8-1ubuntu1.2`).
Sieve's matching engine validates package release identifiers against authoritative distro security advisories, preventing false positive alarms generated by naive upstream version checks.
